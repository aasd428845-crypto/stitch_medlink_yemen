# تقرير المرحلة الخامسة — إدارة حسابات السائقين

**التاريخ:** 4 أغسطس 2026  
**الحالة:** ✅ مكتملة ومدمجة

---

## ملخص تنفيذي

المرحلة الخامسة تُمكّن مدير الفرع من إنشاء حسابات السائقين وإدارتها (تفعيل / إيقاف / إعادة تعيين كلمة المرور) مباشرةً من داخل التطبيق دون الحاجة إلى تسجيل الخروج أو الوصول إلى لوحة Supabase. كل العمليات الحساسة تمر عبر **Supabase Edge Function** مؤمّنة بـ JWT، مما يضمن أن مدير الفرع لا يستطيع إدارة إلا سائقي فرعه الخاص.

---

## الملفات المُنشأة

### 1. `supabase/functions/manage-driver-account/index.ts`
**Edge Function مستضافة على Supabase** — تستقبل طلبات من مدير الفرع وتنفّذ العمليات المميّزة باستخدام `service_role` key داخلياً.

**الإجراءات المدعومة:**

| الإجراء | الوصف |
|---------|--------|
| `create` | ينشئ مستخدم auth جديد بكلمة مرور مؤقتة، يُفعّل الحساب فوراً (`account_status = active`)، ويُشغّل علامة `requires_password_change = true` |
| `update_status` | يُغيّر `account_status` إلى `active` أو `suspended` |
| `reset_password` | يُعيد تعيين كلمة مرور السائق ويُشغّل `requires_password_change = true` |

**الضمانات الأمنية في الـ Edge Function:**
- التحقق من JWT المُرسَل في `Authorization` header
- التأكد أن المُستدعي هو `branch_manager` نشط (`account_status = active`)
- التأكد أن السائق المستهدف ينتمي لنفس فرع المدير (`branch_id` check)
- رفض أي طلب لسائق من فرع آخر بـ 403

---

### 2. `supabase/migrations/0005_secure_users_rls.sql`
**هجرة قاعدة البيانات** — تُغلق ثغرة أمنية موجودة وتُضيف RPC آمنة.

**ما تم تغييره:**

| البند | قبل | بعد |
|-------|-----|-----|
| سياسة `users_update_own` | تسمح بتعديل أي حقل في الصف (خطر: ترقية الدور ذاتياً) | محذوفة |
| `users_update_own_profile` (جديدة) | — | تسمح فقط بتعديل `name` و`phone`؛ `WITH CHECK` يمنع تعديل `role` أو `account_status` أو `branch_id` أو `requires_password_change` |
| `clear_requires_password_change()` (جديدة) | — | دالة `security definer` تُصفّر العلامة للمستخدم الحالي فقط بعد تغيير كلمة المرور |

### 3. `medlink_app/lib/services/driver_service.dart`
**خدمة Flutter** — تُغلّف استدعاءات Edge Function وتُدير تدفق تغيير كلمة المرور.

**الدوال:**

```dart
createDriver({name, email, phone, tempPassword})   // ينشئ حساب سائق جديد
updateDriverStatus(driverId, status)               // يُفعّل أو يُوقف حساباً
resetDriverPassword(driverId, newPassword)         // يُعيد تعيين كلمة المرور
changeMyPassword(newPassword)                      // السائق يُغيّر كلمته عبر RPC
```

`changeMyPassword` يستدعي `supabase.rpc('clear_requires_password_change')` بعد تحديث كلمة المرور — لا يكتب مباشرة في `public.users` (يتجنب الثغرة الأمنية).

### 4. `medlink_app/lib/screens/branch_manager/create_driver_sheet.dart`
**نافذة إنشاء سائق** — Bottom Sheet يظهر بالضغط على زر +.

**الحقول:**
- الاسم الكامل (مطلوب)
- البريد الإلكتروني (مطلوب، مع التحقق من الصيغة)
- رقم الهاتف (اختياري)
- كلمة المرور المؤقتة (مطلوبة، 6 أحرف على الأقل)

**بعد النجاح:** يظهر AlertDialog يعرض البريد الإلكتروني وكلمة المرور المؤقتة بشكل قابل للنسخ ليُشاركها المدير مع السائق.

---

### 5. `medlink_app/lib/screens/branch_manager/manage_driver_sheet.dart`
**نافذة إدارة السائق** — تظهر بالضغط على بطاقة سائق موجود.

**الوظائف:**
- عرض اسم السائق، هاتفه، وحالته الحالية (نشط / موقوف / قيد المراجعة)
- زر تفعيل / إيقاف بلون مناسب (أخضر / برتقالي)
- قسم قابل للطي لإعادة تعيين كلمة المرور (حقلان: كلمة المرور الجديدة + تأكيدها)

---

### 6. `medlink_app/lib/screens/auth/change_password_screen.dart`
**شاشة تغيير كلمة المرور الإجباري** — يُوجَّه إليها السائق تلقائياً عند أول تسجيل دخول.

**السلوك:**
- شاشة كاملة لا يمكن تجاوزها (الـ Router يُعيد التوجيه إليها)
- حقلان: كلمة المرور الجديدة + تأكيدها
- زر تسجيل الخروج (في حال رأى السائق أن الحساب خاطئ)
- بعد التغيير الناجح: يُحدّث `AuthController.refreshProfile()` → الـ Router يُوجّه إلى `/driver`

## التدفق الكامل للمرحلة الخامسة

```
مدير الفرع                     Edge Function                  Supabase Auth + DB
──────────────────────────────────────────────────────────────────────────────
1. يفتح تاب السائقون
2. يضغط FAB "إضافة سائق"
3. يملأ النموذج (اسم/بريد/هاتف/كلمة مرور)
4. يضغط "إنشاء الحساب"
                              5. يتحقق من JWT المدير
                              6. يتأكد role = branch_manager + active
                              7. يستخرج branch_id المدير
                              8. يستدعي auth.admin.createUser()
                                                              9. ينشئ auth user
                                                              10. trigger handle_new_user → public.users
                              11. ينتظر 600ms للـ trigger
                              12. يُحدّث: branch_id, account_status=active, requires_password_change=true
13. يعرض بيانات الدخول المؤقتة للمدير
14. المدير يُرسلها للسائق

السائق                         Flutter App                    Supabase
──────────────────────────────────────────────────────────────────────────────
1. يسجل دخوله بالبريد وكلمة المرور المؤقتة
                              2. AuthController.refreshProfile()
                              3. profile.requiresPasswordChange = true
                              4. Router يُوجّه إلى /change-password
5. يُدخل كلمة مروره الجديدة
                              6. supabase.auth.updateUser(password: new)
                              7. supabase.rpc('clear_requires_password_change')
                                                              8. UPDATE users SET requires_password_change=false
                              9. AuthController.refreshProfile()
                              10. requiresPasswordChange = false
                              11. Router يُوجّه إلى /driver
```

## الأمان

| التهديد | الإجراء المُتخذ |
|---------|----------------|
| مستخدم يُرقّي دوره ذاتياً (`role = branch_manager`) | Migration 0005: `WITH CHECK` في `users_update_own_profile` يمنع تعديل `role` |
| مستخدم يُصفّر `requires_password_change` دون تغيير كلمة المرور | لا يمكن كتابة الحقل مباشرةً (محظور بالـ RLS)؛ يُصفَّر فقط عبر `clear_requires_password_change()` |
| مدير يُدير سائقي فروع أخرى | Edge Function تتحقق من `branch_id` قبل كل عملية |
| استدعاء Edge Function بدون تسجيل دخول | الـ Function ترفض أي طلب بلا `Authorization` header صالح |
| مدير موقوف الحساب يستدعي الـ Function | الـ Function تتحقق من `account_status = active` للمدير |
