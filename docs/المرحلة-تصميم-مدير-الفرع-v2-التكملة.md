# المرحلة — تصميم مدير الفرع V2 (التكملة)

## النطاق
استكمال إعادة تصميم واجهة مدير الفرع بعد الدفعة الأولى، مع الحفاظ على منطق الأعمال ومصادر البيانات الحالية وعدم إجراء أي تعديل على قاعدة البيانات.

## الملفات التي تم اعتمادها في الواجهة
- `medlink_app/lib/screens/branch_manager/branch_manager_design.dart`
- `medlink_app/lib/screens/branch_manager/branch_manager_home_shell.dart`
- `medlink_app/lib/screens/branch_manager/branch_dashboard_tab.dart`
- `medlink_app/lib/screens/branch_manager/branch_orders_tab.dart`
- `medlink_app/lib/screens/branch_manager/branch_order_detail_screen.dart`
- `medlink_app/lib/screens/branch_manager/branch_invoices_tab.dart`
- `medlink_app/lib/screens/branch_manager/branch_inventory_tab.dart`
- `medlink_app/lib/screens/branch_manager/branch_drivers_tab.dart`
- `medlink_app/lib/screens/branch_manager/branch_chat_tab.dart`

## مبادئ التصميم
1. RTL أولاً.
2. هوية طبية حديثة تعتمد Midnight Navy مع Cyan/Teal للحالات الإيجابية وAmber للتنبيهات.
3. بطاقات كبيرة بحواف ناعمة وحدود خفيفة وظلال محدودة.
4. إظهار المعلومات التشغيلية المهمة بسرعة: الطلبات، المخزون، الفواتير، والسائقون.
5. عدم وضع أرقام أو حالات تجريبية؛ المؤشرات مرتبطة بالـBranchController والبيانات الفعلية.
6. الحفاظ على Material/Theme الموجود في المشروع بدلاً من إدخال نظام تصميم مستقل.
7. عدم تعديل الخدمات أو نماذج البيانات لمجرد التغيير البصري.

## ما تم استكماله
- شاشة الطلبات مع فلاتر الحالات وإجراءات الإسناد والتحويل والرفض.
- شاشة الفواتير مع إجمالي المبيعات وعدد الفواتير.
- شاشة المخزون بنفس لغة التصميم.
- شاشة السائقين مع حالة التوفر والتقييم وعدد المهام.
- شاشة المحادثات بنفس الحاويات البصرية.
- تفاصيل الطلب وإجراءات الطلب متسقة مع التصميم.
- التنقل السفلي يحافظ على أدوار مدير الفرع الحالية.

## قاعدة البيانات
لا توجد Migration جديدة؛ هذه المرحلة UI فقط.

## قرار معماري
تم استخدام `branch_manager_design.dart` كمجموعة مكونات مشتركة لتقليل تكرار التصميم وضمان أن أي شاشة جديدة لمدير الفرع تستخدم نفس الهوية.

## اختبار مطلوب
- تشغيل `flutter analyze`.
- تشغيل اختبارات المشروع الموجودة.
- اختبار تسجيل الدخول بدور مدير الفرع.
- اختبار تحميل الطلبات والمخزون والفواتير والسائقين.
- اختبار النقر على تفاصيل الطلب وإجراءات الإسناد والتحويل والرفض.
- اختبار RTL على أحجام الهاتف المختلفة.
